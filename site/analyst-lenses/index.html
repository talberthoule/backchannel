One request reads the call through every lens

Backchannel's analyst reads the latest stretch of a live call once, through every lens you configure, and tags each finding with the lens that found it. This page shows why it works that way and what happens on each cycle, using a real run on a fictional account.

In the app

What it looks like in Backchannel

The same run, on the same fictional account. The Delivery Risks lens was added through Admin, and its findings came back from the model tagged risk.

Configure a lens

Admin → Agents → Consolidated Analyst. A lens is a name, an insight type, and a prompt section. Pick one of the four built-in types, or type a new one and the app treats it as its own kind of finding. Switching a lens off removes its section from the next request.

During the call

Every card carries the lens that found it, so a renamed or custom lens shows up under its own name. The filter row gains a chip for each type present in the feed, custom types included.

After the call

The Insights tab gives each type its own section, headed by the lens name. Each card keeps its speaker, the rationale, and the line that triggered it.

How it works, precisely

Defaults as shipped in v0.6.5. File paths point into the open-source repository, relative to backend/app/ unless noted.

PartBehaviorSource
CycleEvery 40 seconds by default, plus one final pass at End Call. A cycle is skipped when the transcript has not changed.services/agents/orchestrator.py
WindowThe latest 30 transcript lines from the last five minutes, with speakers tagged S1, S2 and so on.services/agents/base.py
LensA name, an insight type and a prompt section, stored with the analyst's settings. The prompt asks for at most 3 findings per lens.services/agents/prompts.py
ReplyEvery finding has the same seven fields whatever lenses are on. The lens decides the item_type and lens values.services/agents/consolidated_analyst.py
ChecksFindings of a type with no enabled lens are dropped. So are near-repeats of insights saved in the last five minutes.services/agents/orchestrator.py
Meeting typeThe Opportunity lens is only sent for client and customer delivery conversations, where offering matching runs.services/meeting_context.py
Custom typesGet a badge, a filter chip, a post-call section and an export label. Answer tracking stays with questions, and offering matching with opportunities.frontend/src/utils/insightTypes.ts
Trade-offAll lenses share one model, one cycle and one transcript window. If that request fails, the cycle produces nothing for any lens.services/agents/consolidated_analyst.py

Alderwake Health Network and everyone in it are fictional. The call comes from the showcase seed in showcase/seed_demo.py. Step 1 sketches the design Backchannel avoids, so its three findings are examples. Everything from step 3 on is real output: three analyst cycles run with gemini-3.8-flash on 25 September 2026 against an isolated demo stack, then rendered by the app. Before saving, each finding went through the orchestrator's word-overlap test against every insight already in the session, which dropped two in the cycle shown. That cycle returned six findings in 4.8 seconds.
