# Backchannel v0.2.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish all Backchannel changes since `v0.1.1` as `v0.2.0` across Docker source, the documentation site, and Linux, macOS, and Windows desktop bundles.

**Architecture:** Reuse the repository's tag-driven desktop workflow and master-driven site workflow. Fast-forward the clean release branch into `master`, add only the existing release metadata and current-version link updates, validate every delivery path, push the tag first, and push `master` only after all desktop assets pass.

**Tech Stack:** Git, GitHub Actions, PyInstaller, Docker Compose, React/Vite, Astro/Cloudflare Workers, Python `unittest`

## Global Constraints

- Release version is exactly `v0.2.0`.
- Keep GitHub release assets private; do not change repository visibility or create public mirrors.
- Ship exactly `Backchannel-windows-x64.zip`, `Backchannel-macos-arm64.zip`, and `Backchannel-linux-x64.tar.gz`.
- Do not add MSI, DMG, DEB, RPM, signing, a container registry, or a second version source.
- Keep `v0.1.0` and `v0.1.1` pages, notes, and tags unchanged.
- Do not push `master` until the tag workflow and all three desktop assets are verified.

```markdown
# Backchannel v0.2.0

This release adds private early-access administration, richer meeting chat
context, and a portable Linux desktop bundle.

## Highlights

- Capture early-access requests in Cloudflare D1 and review them through a
  Cloudflare Access-protected operator page.
- Ground meeting chat in briefings, saved insights, speaker-attributed
  transcripts, and recent follow-up context.
- Clarify interest-request failures and harden chat-context construction.
- Ship Linux x64 beside the existing Windows x64 and macOS arm64 bundles.

## Downloads

- `Backchannel-windows-x64.zip` - Windows 10 or later, x64
- `Backchannel-macos-arm64.zip` - macOS on Apple Silicon
- `Backchannel-linux-x64.tar.gz` - portable Linux x64 bundle

All desktop bundles are unsigned and remain available through authenticated
access to this private repository. Docker Compose users receive the same code
by rebuilding from the `v0.2.0` source tag.
```

### Task 4: Commit and publish the tag

**Files:**
- No intended source changes

**Interfaces:**
- Consumes: verified release candidate
- Produces: immutable annotated `v0.2.0` tag and GitHub Release assets

- [ ] **Step 1: Verify the release commit is clean**

```powershell
git status --short --branch
git show --stat --oneline --decorate HEAD
```

Expected: `master` is clean and `HEAD` is the reviewed
`release: publish v0.2.0` commit.

- [ ] **Step 2: Tag and push the tag first**

```powershell
git tag --list v0.2.0
git ls-remote --tags origin refs/tags/v0.2.0
git tag -a v0.2.0 -m "Backchannel v0.2.0"
git push origin v0.2.0
```

Expected: both pre-tag checks return no tag, then the remote accepts the new
annotated tag without moving an existing tag.

- [ ] **Step 3: Wait for the desktop workflow**

```powershell
$releaseSha = git rev-parse HEAD
$runId = gh run list --workflow desktop-release.yml --event push --commit $releaseSha --limit 1 --json databaseId --jq '.[0].databaseId'
gh run watch $runId --exit-status
```

Expected: Windows, macOS, and Linux matrix jobs all succeed.

- [ ] **Step 4: Verify release assets and access policy**

```powershell
$assetDir = Join-Path $env:TEMP 'backchannel-v0.2.0-assets'
New-Item -ItemType Directory -Force $assetDir | Out-Null
gh release view v0.2.0 --json tagName,targetCommitish,assets
gh release download v0.2.0 --dir $assetDir
Get-ChildItem $assetDir | Select-Object Name,Length
```

Expected: the tag targets the release commit, all three required non-empty
assets download with authenticated access, and an unauthenticated release or
asset request returns 404.
